The VFS is Cebian's virtual file system inside the browser. It's not a real directory on your computer, and paths like `/workspaces/` and `~/.cebian/skills/` won't show up in Finder or File Explorer.

Think of it as Cebian's own local file area: model-generated files, Prompts, Skills, cross-conversation memories, and materials in session workspaces are all stored here.

## What's stored

The VFS mainly has a few kinds of directories:

- `/workspaces/{sessionId}/`: each conversation's own workspace. When Cebian generates files such as reports, tables, or images in a conversation, they generally go here.
- `~/.cebian/prompts/`: the prompt files for Slash Prompts.
- `~/.cebian/skills/`: Skill folders; each Skill is usually a whole directory.
- `~/.cebian/memories/`: cross-conversation memory files.
- `~`: equivalent to `/home/user`, just a virtual user directory.

For everyday use, you don't need to memorize these paths. You only encounter them when viewing files Cebian generated, organizing Prompts / Skills, or troubleshooting file links.

## How it works

The VFS lives in the browser extension's own IndexedDB. That means:

- The data is stored in your local browser; it won't be uploaded to a server just because Cebian has a VFS.
- VFS file tools are isolated from your real disk and do not grant arbitrary local-file access. Uploading files, allowing file-URL access, and connecting external tools are separate ways to provide data.
- When you uninstall the extension or clear the browser extension's data, the files inside may be deleted along with it.

Local storage does not mean content can never leave the device: content returned by a file-reading tool may enter the model's context. WebDAV backups send the selected files to your configured server.

Cebian's file tools read and write this very VFS. For example, when the model generates a Markdown report for you, it actually creates a `.md` file in the VFS and then gives you a clickable link in the conversation.

## How to open it

The most common way is to open it from a file link in a conversation.

When Cebian creates or saves a file, it usually provides a link such as "View file" or "Open directory" in its reply. Clicking it opens a standalone VFS browser page.

In the VFS browser, you can:

- View directories and files
- Preview text, code, Markdown, HTML, SVG, images, audio/video, and PDF
- Copy paths; for text-based files, copy the source contents too
- Download a single file
- Download an entire directory as a zip

If you're just managing Prompts or Skills, prefer the corresponding pages in Settings; the VFS browser is better suited for viewing file results and workspace content.

## Preview and download limits

Files over **50 MiB** are not previewed in the browser; download them instead. Unsupported binary formats such as archives are also download-only. Audio and video playback depends on the codecs your browser supports.

### PDF

PDFs render page by page in the VFS page. Scrolling updates the current page indicator; use the bottom "− / +" controls to zoom. Password-protected PDFs cannot be previewed here. This is a file viewer, not a chat-attachment upload feature, and it does not provide PDF text search or OCR.

## HTML preview and source

HTML, Markdown, and SVG support "Preview / Source" at the top-right. Code files display syntax-highlighted source directly. HTML opens in Preview by default; the same VFS page remembers your view choice separately for each file type.

### HTML security boundaries

- **Chrome / Edge and other Chromium browsers**: HTML runs in an isolated sandbox. It can execute inline scripts, load HTTPS scripts and resources, and make permitted network requests. It cannot access extension APIs or extension storage, but sandboxing does not mean offline operation or prevent HTML from sending its own contents to external services.
- **Firefox**: static preview does not allow scripts, so JavaScript-dependent interactions do not run. Static preview does not mean all external resource loading is disabled.

Only preview HTML you trust, and do not enter keys or other sensitive information into it. Source view displays text without executing its HTML scripts. However, files open in Preview by default: switching to Source does not mean scripts have not already run.
