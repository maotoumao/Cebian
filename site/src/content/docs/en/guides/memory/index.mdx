By default every new conversation in Cebian starts from scratch — it doesn't remember what you said last time. Memory lets the AI save the "about you, useful later" bits as local files during a chat, and automatically brings the relevant ones into your next conversation.

This feature is off by default; you turn it on yourself in settings.

![Screenshot](./snapshot.png)

## Enabling memory

Open "Settings → Memory" and turn on "Enable memory" to include memory instructions, your core profile, and the index in conversations. Turning it off stops automatic injection and automatic organizing; it does not delete files or block file-tool access. You can still manage existing memories in settings.

## How memory is stored

Each memory is a Markdown file under `~/.cebian/memories/` (in the VFS, not a real folder on your computer). The AI uses the ordinary file tools to write them, which is why you can see its "Remembering…" actions during a chat.

With memory enabled, every turn includes a compact index: titles, types, descriptions, time since modification, and file paths. The AI reads individual files when it needs details. The index has a size limit and may be truncated; it does not include every full body.

One file is special: `user_profile.md` holds your core profile (name, role, language, accessibility needs, etc.). Its body is included in full each turn when within the size limit; an oversized profile uses its description and a read-file hint instead, so keep it short.

## What gets saved, what doesn't

What it saves is "cross-conversation, useful later" information, such as:

- Who you are, what you do, what language you prefer
- Long-term preferences (e.g. "lead with the conclusion", "no redundant comments in code")
- Where your things live (e.g. your tasks all sit in a certain Notion)

The prompt tells the AI not to save the following (this is not an automatic sensitive-data filter):

- Sensitive content like passwords, tokens, cookies, payment and form data
- One-off task state and the temporary context of the current conversation
- Web page content it can read directly from the page or re-fetch anytime

Even if you say "remember this" outright, the AI first judges which part is actually worth keeping long-term.

## Memory types

Each memory has a type to keep things organized:

- user: core facts about you (consolidated into `user_profile.md`)
- feedback: a correction or confirmation about something the AI did
- context: background on something you're working on
- reference: where your frequently used resources or external info live

## Viewing and managing

View, edit, or delete memory files under "Settings → Memory". Deleted files stop appearing in subsequent automatic injection; deletion does not retract content already included in past messages, sent to a model service, or saved in backups.

## Organizing memory

As memories pile up they get duplicated, stale, and scattered. Organizing has a temporary background AI read through them all and merge duplicates, drop stale notes, and tidy the bodies.

- Manual: click "Organize" on the memory page to run it right away.
- Automatic: with "Auto organize" on, background checks run periodically. Organizing starts only when enough time has passed since the last successful run (14 days by default), enough memories have been added or changed (30 by default), and no conversation is running. Failed or conflicting attempts also delay automatic retries.

You can select a separate organizing model; otherwise Cebian uses the last-selected conversation model. It also tries that fallback if the dedicated model is unavailable or has tool calling turned off. Organizing requires file-tool support and uses model credits. You can adjust the interval and changed-file threshold; the first run has no previous success time, so it need not wait 14 days.

The organizing AI can only work in a temporary copy. Before committing, Cebian checks file format and whether the original memories changed; failed checks or detected conflicts discard the result. This cannot guarantee the AI preserves every fact, and the final file replacement is not atomic. Avoid editing memories during organizing and back up important content first.

## Backup

Memory can be included in a backup on its own. When creating a backup under "Settings → Data", just tick "Memory"; you can also choose whether to restore memory separately. If you want to keep your memories after switching devices, remember to include it in a full or partial backup.

## Privacy

- Local storage does not mean local-only processing: the core profile and index are sent with conversations to the selected model; file bodies read on demand also enter its context. The organizing model reads memory contents too. Using a remote model involves transmission to that service.
- WebDAV backups that include memory also upload the files to your configured server.
- Inspect, edit, and delete memories in settings. Do not save passwords, tokens, or other secrets as memories.
- Prompts instruct the AI to exclude sensitive information and web-page instructions and treat memory as lower-priority context. These are behavioral constraints, not absolute guarantees against disclosure or prompt injection.
