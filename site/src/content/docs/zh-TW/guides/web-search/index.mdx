當問題需要當前頁面以外的資料時，Cebian 會呼叫 `web_search` 工具：在一個後臺標籤頁裡開啟搜尋引擎，讀取結果，再把「標題 + 連結 + 摘要」交給模型。

用哪些引擎、先試哪個、被攔了換誰，都由你在設定裡決定。

## 它是怎麼工作的

預設按列表順序嘗試已啟用的搜尋引擎。模型也可以根據「適用場景」指定先嚐試某個引擎，其餘引擎仍按列表順序嘗試：

1. 把搜尋詞填進該引擎的地址模板，在後臺標籤頁裡開啟。
2. 頁面載入完成後，在結果頁裡執行該引擎的「抽取指令碼」，得到結構化結果。
3. 拿到結果就停下；如果引擎返回「被攔截」（比如出現驗證碼）、沒有結果或指令碼出錯，自動換下一個。
4. 沒有取得可用結果時，工具會彙總各引擎的情況，包括沒有結果、被攔截、執行失敗，以及因時間預算耗盡而未嘗試的引擎，供模型說明原因並決定下一步。

Cebian 會盡量複用同一個搜尋標籤頁，建立時不會切換你當前正在看的標籤頁。搜尋標籤頁被關閉、轉去其他網站或無法繼續使用時會重新建立；擴充套件後臺重新啟動後也可能建立新標籤頁。你可以隨時切換過去檢視。

## 調整順序與啟停

入口在「設定 → 對話 → 聯網搜尋」。

- 列表的順序就是回退順序，第一個開著的引擎標為「首選」。用每行右側的「⋯」選單可以上移、下移。
- 用開關停用某個引擎。比如你所在地區打不開 Google，把它關掉或挪到最後即可。
- 內建了 Bing、Brave、Google、DuckDuckGo 和百度。百度預設標註「中文查詢」，模型會在中文問題上優先考慮它。

## 修改內建引擎

點一行進入編輯頁，可以改搜尋地址、抽取指令碼和「適用場景」。名稱跟隨介面語言，不可改。

修改過搜尋地址、抽取指令碼或適用場景的內建引擎會標為「已修改」。在「⋯」選單裡選「恢復預設值」可立即還原；在編輯頁點「重置」後還需點「儲存」。兩種操作都保留啟停狀態和列表順序。

搜尋引擎改版導致結果讀不出來時，不必等 Cebian 發新版，自己改一下指令碼就好。

## 新增自定義引擎

點「新增引擎」，需要填：

- **名稱**：列表裡顯示的名字，比如 `Kagi`。
- **搜尋地址**：用 `{query}` 佔位搜尋詞，比如 `https://kagi.com/search?q={query}`。Cebian 會把搜尋詞做 URL 編碼後填進去。
- **抽取指令碼**：在結果頁裡執行的一段 JavaScript，見下節。
- **適用場景**（可選）：一句話說明什麼時候優先用它，會寫進工具說明給模型參考。

不熟悉寫指令碼也沒關係：在指令碼編輯器上方的輸入框裡填結果容器的 CSS 選擇器（比如 `#results`），點「生成模板」會得到一份能跑的起手指令碼。模板會替換編輯器裡的現有指令碼；生成後仍要按頁面結構調整結果條目、標題和摘要的選擇器。也可以在對話裡讓 Cebian 檢視目標引擎的結果頁並協助編寫，再把指令碼貼進編輯器。

## 抽取指令碼

指令碼必須定義一個完整的 `extract` 函式，在搜尋結果頁裡執行：

```js
function extract({ document, query }) {
  const root = document.querySelector('#results');
  if (!root) return { status: 'empty', results: [] };

  const results = [...root.querySelectorAll('.result')].map((el) => {
    const a = el.querySelector('a[href]');
    if (!a) return null;
    return {
      title: a.textContent.trim(),
      url: a.href,
      snippet: el.querySelector('.snippet')?.textContent?.trim() ?? '',
    };
  }).filter(Boolean);

  return { status: 'ok', results };
}
```

返回值的三種 `status`：

- `ok`：結果容器在，`results` 是抽到的條目。可以是空陣列，表示引擎確實沒有結果。
- `empty`：結果容器還沒出現。有些引擎在頁面載入完之後才渲染結果，Cebian 會短暫重試幾次。
- `blocked`：明確識別到驗證碼或攔截頁。Cebian 不重試，直接換下一個引擎。

每條結果需要 `title` 和 `url`（必須是 http 或 https 地址，相對地址會按當前頁面解析），`snippet` 可選。不合規的條目會被丟棄。

有些引擎會把結果連結包成跳轉地址（比如 Bing 的 `bing.com/ck/…`），內建腳本里有解包的寫法可以參考。

	<QAItem q="全部停用會怎樣？">模型調用搜索時會得到一條明確的錯誤，提示你到設定裡至少開啟一個引擎。</QAItem>

	<QAItem q="配置會隨備份走嗎？">會。引擎順序、啟停、你改過的內建引擎和自定義引擎都包含在「設定 → 資料」的備份裡。</QAItem>
