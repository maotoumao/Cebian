Cebian 本身不提供模型額度。你需要在「設定 → AI 提供商」裡接入自己已有的訂閱或 API Key，然後在對話輸入框裡選擇模型。

下面只是當前內建 Provider 的列表。實際可用模型會隨各家服務變化，以設定頁裡能選到的模型為準。

## OpenAI Compatible

如果你使用的是 OpenAI 相容介面，也可以自己新增 Provider。

常見場景包括：

- 本地執行的 Ollama / LM Studio
- 自己部署的 vLLM、LiteLLM 或閘道器服務
- 公司內部的 OpenAI 相容介面

在「設定 → AI 提供商」新增自定義 Provider，填寫名稱、Base URL、API Key（如需要），並至少加入一個模型。這裡使用 OpenAI Chat Completions 相容協議。

### Base URL 怎麼填

填 API 的基礎地址，不是網頁首頁，也不是完整的 `/chat/completions` 地址。Cebian 獲取模型時會在其後追加 `/models`，不會自動替你補 `/v1`。

| 服務示例 | Base URL 示例 |
| --- | --- |
| Ollama 本機服務 | `http://localhost:11434/v1` |
| LM Studio 本機服務 | `http://localhost:1234/v1` |
| OpenAI 相容閘道器 | `https://api.example.com/v1` |

埠和路徑以你的服務配置為準；`localhost` 指執行瀏覽器的裝置。服務無需認證時 API Key 可以留空。自定義 Provider 儲存時不做連通性測試，「已配置」不代表請求一定成功。

### 自定義 Headers

在「高階設定」裡新增所需請求頭，例如閘道器要求的 `api-key`。Headers 會用於自動獲取模型和對話請求。若使用自定義 `Authorization` 鑑權，請清空 API Key；同時填寫時 API Key 優先，介面會提示衝突。

備份自定義 Provider 時，模型與端點屬於「普通設定」，API Key 和全部自定義 Headers 屬於「金鑰資訊」。遷移完整配置時應同時包含兩類。

## 自定義模型介面

在自定義提供商的編輯表單中，點模型旁的設定按鈕，可以填寫上下文視窗、最大輸出，並設定思考和多模態能力。能力引數應按實際服務填寫，開啟開關不會讓服務獲得它原本不支援的能力。

不支援工具呼叫的模型，關閉「工具呼叫」即可用於普通對話；關閉後不能呼叫瀏覽器、檔案或 MCP 工具。

### 獲取與批次選擇模型

點選「自動獲取」後，在彈窗中搜索、勾選模型，再確認：

- 這次遠端列表中的模型以勾選為準；取消勾選的已有模型會從草稿移除。
- 繼續選中的已有模型保留思考、多模態、工具呼叫、上下文視窗和最大輸出設定。
- 不在本次遠端列表中的已有模型（包括未被服務列出的手動項）原樣保留；若手動項也在遠端列表中，則同樣以勾選為準。
- 取消彈窗不改變模型列表。確認只修改草稿，最後點選「新增」或「儲存」才生效。

獲取失敗或列表不完整時，可以按服務給出的準確模型 ID 手動新增。先檢查 Base URL、認證和網路；獲取成功也只代表能讀取模型目錄，不代表每個模型都有呼叫許可權或支援工具。

點選模型列表旁的「選擇」，可以勾選多個模型或全選，再批次刪除。刪除只修改當前表單草稿，點選「儲存」才生效；「取消」會放棄這次編輯。
